# P4 验收清单：留痕规范与巡检

## 已实现范围

- `src/rules/gate.ts` 提供状态门禁；工作台和任务详情的状态流转、归档操作均调用门禁，仓储层也会再次校验。
- 办结和归档不可用时禁用操作，并提供缺口清单及“去补”入口；依据/备注可直接聚焦，附件入口会预选对应角色。
- 依据附件文件名中的 `〔YYYY〕N号` 或 `[YYYY]N号` 会自动写入依据并提示核对；JPEG EXIF `DateTimeOriginal` 会记录为 `capturedAt`。
- `src/rules/audit.ts` 每日首次巡检并缓存 `audit-YYYY-MM-DD`；看板按红/黄/绿展示规则结果和已完成留痕完整率。
- 红色问题任务在工作台列表置顶标红并禁用归档；顶部显示红色问题任务数和未归类附件数。
- 新建任务默认备注模板为“办理结果 / 依据摘要 / 后续事项”。模板标题本身不算实际办理说明，办结仍需填写内容。

## 浏览器验收

- [x] `npm run build` 通过（TypeScript 与 Vite 生产构建）。
- [ ] 创建进行中任务，不填写依据、佐证、办理说明；办结按钮禁用，缺口清单包含“结果佐证”“办理说明”（无依据时另列“办理依据”）。
- [ ] 在缺口清单点“去补”：依据/备注可聚焦到对应字段；佐证可打开附件区域并预选“佐证”。
- [ ] 补齐依据、上传佐证并填写办理说明后，办结操作可用。
- [ ] 上传 `X发〔2026〕3号.pdf` 并归类为“依据”；任务依据自动包含 `〔2026〕3号`，页面显示待确认提示。
- [ ] 上传带 `DateTimeOriginal` 的 JPEG，检查 IndexedDB 中附件 `capturedAt` 为 EXIF 拍摄时间。
- [ ] 将附件归为“其他”，顶部出现未归类附件黄条；任务归档门禁列出附件归类缺口。重新归类后可继续归档。
- [ ] 创建“已完成”但没有已上传佐证附件的任务；`/audit` 显示红色“已完成无佐证”，任务列表置顶标红且归档禁用。
- [ ] 对照已完成任务，核对看板留痕完整率分子/分母；周环比显示近 7 天与前 7 天的完整率变化。
- [ ] 巡检结果写入当天 `localStorage` 的 `audit-YYYY-MM-DD`；当天再次打开复用缓存。

## 备注

- 规则按任务和附件元数据运行；文号核对使用佐证附件的文件名与备注，不会下载或解析附件正文。
- “待上传超过 24 小时”从本阶段新增的 IndexedDB `pendingUploads.createdAt` 计算；已有队列记录没有该字段时不推断其等待时长。
- JPEG EXIF 时间为可选元数据；文件没有 `DateTimeOriginal` 时不会生成 `capturedAt`。
